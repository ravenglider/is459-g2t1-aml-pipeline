Every column explained

ColumnMeaning in Ryan’s current SQL
from_bankSender-bank identifier for the directed corridor, for example 260802. This is an ID, not a bank name or amount.
to_bankReceiver-bank identifier for that directed corridor. 260802 → 264284 and 264284 → 260802 are separate rows.
direct_laundered_usdSum of amount_paid_usd for retained, labelled laundering transactions directly from from_bank to to_bank. Ryan’s input is HI-Medium, cross_bank=1 and amount_paid_usd < 20,000,000. total_laundering_in_path_usdRyan’s shared-attempt context value: for each annotated laundering attempt touching both banks, sum that attempt’s retained labelled transaction amounts; then sum across their shared attempts. It is not a confirmed chronological A→B→C path, a direct transfer between the pair, or necessarily unique original funds. A scheme can transfer the same funds across multiple hops, and its attempt value is attributed to multiple bank pairs.
extra_laundering_value_usdmax(total_laundering_in_path_usd − direct_laundered_usd, 0). This is Ryan’s proxy for additional laundering context beyond the direct corridor. It is not verified newly detected or recovered money.
blindspot_gapextra_laundering_value_usd / total_laundering_in_path_usd when the denominator is positive; otherwise Ryan’s SQL returns 0. A value of 0.92 means 92% under this proxy. A value of 1.00 means direct labelled value is zero while shared-attempt context is positive. A zero can also reflect missing shared-attempt coverage, so it is not proof of no information gap.

The leftmost # column: Athena’s displayed result-row number. It is not a stored rank field or bank ID. Results (20) means the query returned up to the requested 20 rows, not that the table contains only 20 pairs.

SELECT COUNT(*) AS labelled_rows,
 COUNT_IF(amount_paid_usd >= 20000000) AS excluded_large_rows,

Your second query result — why four zeros are good

The query checks the population selected by dataset = 'HI-Medium' AND is_laundering = 1 AND amount_paid_usd < 20000000. It returns one summary row for that population, not one result row per transaction.

  • bad_banks = 0: no selected row has a null from_bank or to_bank. Neo4j can use those bank identifiers as graph endpoints. This checks completeness, not whether each ID maps to a real-world institution.
  • bad_accounts = 0: no selected row has a null or empty sending/receiving account string. You can identify account endpoints and test whether one transfer’s receiving account is the next transfer’s sender. Use bank ID plus account ID together. This query does not test whitespace-only strings or account ownership.
  • bad_times = 0: no selected row has a null txn_ts. You have timestamps available to order hops. This does not prove that any particular pair of transfers forms a chain or that its time gap is within 24 hours; Task 5 tests those conditions.
  • duplicate_txn_ids = 0: total selected rows equals the number of distinct non-null txn_id values. Every selected row therefore has a non-null, distinct transaction ID in this checked population. This supports identifying transactions during import and avoiding accidental merging. It does not guarantee uniqueness for other datasets or later runs, so repeat the check when changing scope.

Why these fields matter: banks become bank nodes, bank+account identifiers become account nodes, transfers become relationships, transaction IDs distinguish those relationships, and timestamps let you test chronological paths. Missing values or repeated identifiers could cause incorrect nodes, missing edges or misleading paths.

This is enough to proceed with the next setup task once the remaining population/date columns are recorded. It does not mean the entire dataset is error-free, that the graph is already imported, or that you have found a continuous laundering chain.

No attempt_id requirement: this query intentionally does not reject missing attempt_id. Keep eligible laundering transactions without an annotation. Bank/account continuity and timestamps support your path analysis; attempt_id is optional additional context.

cd "$HOME/role4"
role4_total_kib=$(awk '/MemTotal:/ {print $2}' /proc/meminfo)
role4_available_kib=$(awk '/MemAvailable:/ {print $2}' /proc/meminfo)
if [ "$role4_total_kib" -lt 3500000 ]; then
  echo 'STOP: this launch profile requires a host with at least about 4 GiB RAM.'
elif [ "$role4_available_kib" -lt 2700000 ]; then
  echo 'STOP: insufficient available memory. Check existing workloads before launching.'
elif sudo docker container inspect role4-neo4j >/dev/null 2>&1; then
  echo 'STOP: role4-neo4j already exists. Inspect/reuse it rather than creating another.'
elif [ -e .env ]; then
  echo 'STOP: an existing .env was found. Check previous setup before changing credentials.'
else
  (
    set -e
    umask 077
    read -r -s -p 'Choose Neo4j password (at least 12 characters): ' role4_pass
    printf '\n'
    if [ "${#role4_pass}" -lt 12 ]; then
      echo 'STOP: password must be at least 12 characters.'
      exit 1
    fi
    printf 'NEO4J_AUTH=neo4j/%s\n' "$role4_pass" > .env
    unset role4_pass
    sudo docker pull neo4j:5.26-community
    sudo docker run -d --name role4-neo4j --restart unless-stopped \
      --memory=2560m --memory-swap=2560m \
      -p 7474:7474 -p 7687:7687 \
      --env-file "$HOME/role4/.env" \
      -e 'NEO4J_PLUGINS=["graph-data-science"]' \
      -e 'NEO4J_dbms_security_procedures_unrestricted=gds.*' \
      -e NEO4J_server_memory_heap_initial__size=512M \
      -e NEO4J_server_memory_heap_max__size=1G \
      -e NEO4J_server_memory_pagecache_size=512M \

      -v role4-plugins:/plugins \
      -v "$HOME/role4/import:/var/lib/neo4j/import:ro" \
      neo4j:5.26-community

fi
